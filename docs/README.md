# Документация Pegas

Пользовательская документация CLI Pegas — руководства по командам для
разработчиков и ИИ-агентов (Cursor, Claude Code, Cline, Copilot).

* **Рантайм-зависимости:** 0 (только стандартные модули Node 24+).
* **Инструменты разработки:** Bun 1.4+ (`bun build`, `bun run test`, `tsc`).
* **Краткое представление продукта:** см. [README.md](../README.md) в корне репозитория.

---

## Руководства по командам

1. [**Справочник команд CLI**](./commands.md) — канонический список команд, аргументов и флагов Pegas CLI.
2. [**`pegas init`**](./init.md) — инициализация проекта в деве и шлюза на сервере.
3. [**`pegas dev`**](./dev.md) — локальная разработка с HTTPS, авто-поиском портов и поднятием баз данных.
4. [**Команды управления шлюзом**](./manage.md) — `list`, `remove`, `reload`, `status`, `llms`.
5. [**`pegas add`**](./add.md) — императивное добавление маршрута домена к контейнеру.

---

## Общие флаги
* `--json` — выводит структурированный JSON вместо форматированного текста (поддерживается всеми командами).
* `--gateway-dir <путь>` — явно указывает каталог шлюза (по умолчанию ищет в текущей папке или `~/.pegas/gateway`; если шлюза нет — создаёт его автоматически при первом `pegas deploy`).
* `-h, --help` — справка по командам.
* `-v, --version` — версия утилиты.

## Тестирование и верификация

1. **Unit-тесты (`bun run test`)**:
   - 64 теста в 9 файлах рядом с кодом (`src/**/*.test.ts`): парсинг CLI, генератор Caddyfile, хирургия портов compose, DNS-проверки, анти-хайджекинг, локальный dev, кэш Caddy и табличный вывод.
2. **Unified E2E (`bun run test:e2e`)**:
   - Сквозной 11-фазный рантайм-тест в герметичной песочнице с реальным Caddy, мульти-тенант деплоем, доставкой физического HTTP-трафика (`curl`), защитой от сбоев и переиспользованием образов из локального хранилища Docker.
3. **Локальный Dev E2E (`bun run test:e2e:dev`)**:
   - 5-фазный тест HTTPS-проксирования локального сервера разработки, разрешения конфликтов портов (8443+), изоляции процессов и смарт-поднятия баз данных (`--infra`).
4. **Совместимость с реальными репозиториями (`bun run test:e2e:init <path-or-url>`)**:
   - Автоматическая изолированная проверка выполнения `init` на реальных проектах (подробнее в [документации init](./init.md#3-тестирование-совместимости-на-реальных-репозиториях-e2einit)).
