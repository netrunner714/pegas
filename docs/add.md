# Команда `pegas add`

Создаёт конфигурационный файл маршрута `conf.d/<домен>.caddy`, проверяет его валидность и применяет без даунтайма.

---

## Использование

```bash
pegas add <домен> --upstream <сервис:порт> [опции]
```

### Основные флаги:
* `-u, --upstream <сервис:порт>` — целевой контейнер и порт во внутренней сети `pegas-network` (например: `app:8080`).
* `--no-www` — отключить автоматический редирект с `www.<домен>` на `https://<домен>` (по умолчанию редирект создаётся для всех доменов 2-го уровня).
* `--spa` — режим SPA + API:
  * `--api-prefix <путь>` — префикс API (по умолчанию `/api/*`).
  * `--api-upstream <сервис:порт>` — апстрим бэкенда.
* `--dry-run` — вывести сгенерированный текст конфига в консоль без записи и без перезагрузки Caddy.
* `--force` — перезаписать существующий файл `conf.d/<домен>.caddy`.

---

## Порядок выполнения

1. **Проверка шлюза на сервере:**
   Если в `~/gateway` отсутствует `Caddyfile`, команда автоматически запускает процедуру серверной инициализации (создаёт сеть `pegas-network` и запускает контейнер Caddy).
2. **Генерация файла:**
   Создаёт `conf.d/<домен>.caddy` со сжатием `gzip zstd` и заголовками безопасности (HSTS, nosniff, Referrer-Policy).
3. **Валидация (`caddy validate`):**
   Проверяет синтаксис внутри контейнера. При ошибке файл немедленно удаляется (откат), изменения не применяются.
4. **Применение (`caddy reload`):**
   При успешной валидации Caddy на лету подхватывает новый маршрут без остановки контейнера и разрыва соединений.
