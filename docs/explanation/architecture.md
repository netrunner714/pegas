# Архитектура Pegas

> Объяснение, как устроен Pegas и почему выбраны эти решения.
> Для пошаговых задач — [руководства](../README.md), для точных
> фактов — [справочники](../README.md).

## Проблема

Несколько Docker-проектов на одном VPS наталкиваются на один и тот же набор
конфликтов:

- **Порты 80/443.** Каждый проект хочет пробросить их на хост — первый
  `docker compose up` занимает порты, остальные падают с
  `bind: address already in use`.
- **DNS-коллизии.** Проекты в общей сети с одинаковыми именами сервисов
  (`web`, `app`) — Docker round-robin раскидывает запросы между чужими
  контейнерами.
- **502 на холодном старте.** Обновление маршрутов до готовности приложения
  даёт Bad Gateway на 10–30 секунд.
- **Захват доменов.** Проект B прописывает домен проекта A — и ломает маршрутизацию.
- **Диск.** Неограниченные логи контейнеров молча заполняют VPS.

## Решение: один общий шлюз

Единственный контейнер Caddy (`pegas-gateway`) владеет хостовыми портами
80 и 443. Все прочие контейнеры живут во внутренней сети `pegas-network`
и **никогда** не пробрасывают порты на хост:

```
                Internet (:80 / :443)
                         │
                         ▼
              ┌─────────────────────┐
              │   pegas-gateway     │  ~30 МБ RAM, auto Let's Encrypt
              └──────────┬──────────┘
                         │  pegas-network
          ┌──────────────┴──────────────┐
          ▼                             ▼
   alpha-web:3000                beta-web:8080
   (alias проекта alpha)         (alias проекта beta)
```

Ключевые следствия этой топологии:

1. **Скоуп сетевых алиасов.** Алиас сервиса — `<project>-<service>:<port>`,
   а не просто `web`. DNS-коллизии между проектами невозможны по построению.
2. **Порты принадлежат шлюзу.** Проброс 80/443 в пользовательских compose
   запрещён; конфликт портов исчезает как класс.
3. **Шлюз — общий ресурс машины.** Он не принадлежит первому проекту:
   держатели определяются Docker-метками (`pegas.project`), остановка
   происходит, когда контейнеров других проектов не осталось.

## Декларативный контракт

`pegas.json` коммитится в репозиторий и описывает окружение целиком:
сервисы, порты, домены, инфраструктуру. Все производные артефакты
генерируются из него и не живут дольше команды:

| Артефакт | Жизненный цикл |
|---|---|
| `pegas.json` | Коммитится, единственный источник истины |
| Манифест запуска (Compose) | Эфемерный: передаётся Docker по stdin, не сохраняется на диск |
| Caddyfile dev-прокси | Эфемерный: живёт в памяти процесса `pegas dev` |
| `conf.d/<project>.caddy` на сервере | Серверный рантайм: результат применения контракта |

Это устраняет класс багов «у меня на машине работает»: правила одинаковы
для всех окружений заранее, а не вспоминаются на проде.

## Идентичность контейнеров и идемпотентность

Контейнеры помечаются Docker-метками `pegas.project`,
`pegas.environment`, `pegas.service`, `pegas.manifest-hash`. Хэш —
нормализованная эффективная конфигурация сервиса: он совпадает на разных
машинах для одного контракта (абсолютные пути и секреты в него не входят).

- `pegas deploy` сравнивает хэш по каждому сервису: совпал — контейнеры
  не пересоздаются (идемпотентность); не совпал — пересоздаёт;
- `pegas dev` при расхождении только сообщает, разрушительных действий
  не выполняет;
- Секреты передаются по ссылке (`envFile`), содержимое не попадает в
  манифесты, метки и логи; их изменение отслеживается отдельным
  fingerprint-хэшем.

## Надёжность деплоя

- **Readiness-проба** — маршруты обновляются только после готовности
  контейнеров (состояние + Docker healthcheck): без 502 на холодном старте.
- **Анти-хайджекинг доменов** — деплой останавливается, если домен уже
  принадлежит другому проекту на сервере.
- **DNS pre-flight** — A-записи сверяются с IP сервера до деплоя, чтобы
  не сжечь лимиты Let's Encrypt (`--strict-dns` в CI).
- **Атомарный reload с откатом** — конфигурация валидируется
  (`caddy validate`); при ошибке старая мгновенно восстанавливается.

## Безопасность

- Docker socket **не монтируется** в шлюз (в отличие от Traefik) —
  вектор повышения привилегий исключён.
- Дефолтные security-заголовки: HSTS, `X-Content-Type-Options: nosniff`,
  `Referrer-Policy`.
- Локальный dev — user-space: без sudo, Caddy из `~/.pegas/bin`.
- Ротация логов контейнеров (`max-size: 50m`, `max-file: 3`) — диск не
  переполняется.

## Ноль зависимостей

CLI собран целиком на стандартных модулях Node (`node:fs`,
`node:child_process`, `node:path`, `node:net`). Дерево зависимостей
отсутствует, аудит не нужен, размер бандла — десятки килобайт.
