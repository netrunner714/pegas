# Инициализация проекта (`pegas init`)

> How-to: подключить Pegas к существующему проекту — артефакты, гигиена git, агентные правила.

```bash
# Инициализация текущего проекта
pegas init

# Безопасный предпросмотр без записи файлов
pegas init --dry-run

# Машиночитаемый JSON для AI-агентов
pegas init --json
```

## Что делает `pegas init`

Тонкий детерминированный scaffolder (одно «первое касание», идемпотентен):

1. **`docs/pegas.md`** — канонический файл правил Pegas для проекта (создаётся или
   обновляется до канона установленного CLI). Отсюда агенты узнают контракт, команды
   и доктрину env-доступа.
2. **AGENTS.md** — императивный блок правил Pegas между маркерами
   `<!-- BEGIN:pegas-rules -->` / `<!-- END:pegas-rules -->` (создаёт файл при отсутствии).
3. **`.gitignore`** — дополнение без дублей: `.pegas` (рантайм-каталог), маска `.env*`
   и исключение `!.env.example` (шаблон секретов обязан коммититься).

## Чего `pegas init` НЕ делает (v3)

- **не создаёт и не трогает `pegas.json`** — контракт пишется по схеме и эталону;
- не инвентаризирует docker-compose, не харвестит env, не пишет starter-Dockerfile;
- не поднимает версии зависимостей (для этого `pegas update`).

## Свежесть артефактов

`pegas check` сравнивает `docs/pegas.md` и блок AGENTS.md с каноном установленного
CLI. Устарели (например, зависимость обновлялась без init) — check предупредит,
`pegas init` приведёт к канону. Так документация в репо не гниёт.

## Повторный запуск

Безопасен и идемпотентен: существующие артефакты обновляются до канона,
`pegas.json` и `.env` не затрагиваются. Результат каждой операции выводится списком.
