# Принципы Pegas: файловые артефакты и переносимость окружений

> Статус: **утверждён** (обсуждение сессии 2026-10-30).
> Источник мысли: личный черновик владельца (`docs/draft.md`, не в git) — раздел 17.
> Формат: инвариант (закон) + инвентаризация состояния «сейчас / хотим».

---

## 1. Цель одним абзацем

Каждое окружение точно знает правила работы со своей копией репозитория. `pegas.json` — единый контракт, синхронизируемый через git, — заранее, ещё на машине разработчика, определяет все варианты поведения на любой машине. Это убивает проблему «у меня на пк работает»: конфиги не расползаются по разным файлам одного репо и не прячутся в gitignored-папках разных окружений.

---

## 2. Закон: три категории файлов — и никаких четвёртых

### Категория 1. Коммитится
Всё, что обязано дойти через git до любого окружения: `pegas.json`, пользовательский compose, `package.json`, документация. Это **правила для работы с копией репо** — известные заранее, а не вспоминаемые на проде.

### Категория 2. Эфемерно
Производные артефакты, существующие минуты — в пределах одной команды. Сгенерированный конфиг живёт в памяти процесса и умирает вместе с командой (Ctrl+C в `npm run dev`). Если производный артефакт всё же вынужден появиться на диске — Pegas обязан явно сообщить: *«он генерируемый, нужен буквально на минуту и будет удалён»*.

### Категория 3. Серверный рантайм
Состояние уже задеплоенного: роуты `conf.d/`, контейнеры. Это не «копия репо», а **результат применения правил**. Живёт на сервере столько, сколько живёт деплой.

### Запрещённая категория 4
**«Генерируемый, gitignored, долгоживущий, притворяющийся конфигом».** Файл, который на каждой машине пересчитывается заново, лежит в рабочей директории и выглядит как конфигурация — но не проходит через git и потому может не совпадать между окружениями. Паттерн `node_modules` и `.cache` здесь легитимен (никто не считает их конфигом); производный compose-файл в служебной папке — **нет**.

---

## 3. Позиция Pegas: суверенитет и его граница

Pegas заявляет:

> «Я тут самый главный и мне всё равно, что вы думаете. Не дам конфигам разползтись по репозиториям. Не дам забыть на проде ключ от rate limit, потому что ты забыл флаг в env. Не дам писать в коде `if (dev)` / `if (prod)`».

Граница суверенитета: Pegas управляет **правилами окружения**, а пользователь сохраняет владение **данными приложения**. Состав инфраструктуры (PostgreSQL, Redis и т. д.), её параметры запуска, healthchecks, volumes и связи сервисов описываются в коммитнутом `pegas.json`. Содержимое БД, загруженные файлы и другие пользовательские данные остаются в Docker volumes или внешних хранилищах и не становятся конфигурацией Pegas. Это осознанный сдвиг границы: пользовательский Compose больше не является источником истины и не требуется после `pegas init`.

## 4. Инвентаризация: сейчас / хотим

Проверка кодовой базы на соответствие закону (аудит сессии 2026-10-30):

| № | Артефакт | Категория по закону | Состояние |
|---|---|---|:---:|
| 1 | `pegas.json` | Коммитится | ✅ **сейчас** |
| 2 | `pegas dev` → Caddyfile: генерируется в памяти, передаётся в Caddy без файла на диске | Эфемерно | ✅ **сейчас** |
| 3 | `conf.d/<project>.caddy` на сервере | Серверный рантайм | ✅ **сейчас** |
| 4 | `pegas deploy` → `.pegas/docker-compose.yml`: пересчитывается на каждой машине, gitignored, долгоживущий, выглядит как конфиг | **Запрещённая категория 4** | ❌ **устраняется**: Pegas генерирует манифест только из `pegas.json`, применяет его как эфемерный артефакт и не оставляет Compose-файл в проекте |
| 5 | `docs/pegas.md`, блок Pegas в `AGENTS.md`, скрипты в `package.json` (создаются `pegas init`) | Коммитится | ✅ **сейчас** |

Пункты 1–3, 5 — закон уже соблюдается. Пункт 4 — единственный системный нарушитель; его устранение реализуется в рамках декларативного Docker runtime. После перехода пользовательский Compose не участвует в runtime и может быть удалён из проекта без потери описания окружения.

---

## 5. Практическое следствие для разработки

Любая новая фича, которая хочет что-то записать на диск, проходит фильтр из одного вопроса:

> **«Этот файл доедет через git до любого окружения — или он результат пересчёта на конкретной машине?»**

Первое — коммитится. Второе — либо живёт в памяти команды, либо громко объявляется эфемерным и удаляется. Третьего варианта («тихо лежит в gitignored-папке и притворяется конфигом») не существует.
