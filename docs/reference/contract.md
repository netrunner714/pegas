# Контракт pegas.json (v3)

> Справочник всех полей декларативного контракта. Контракт хранится в корне проекта
> и коммитится в git: он — единственный источник истины о топологии, из него на каждый
> деплой генерируется эфемерный манифест. Машинный источник правды —
> [JSON Schema](https://netrunner714.ru/schemas/pegas.json); эталон — `example.json` в репо pegas.

## Корневые поля

| Поле | Тип | Default | Описание |
|---|---|---|---|
| `$schema` | string | — | URL JSON-схемы: автодополнение и валидация в IDE |
| `projectName` | string | — | slug `^[a-z0-9][a-z0-9-]*$`: основа сетевых алиасов, compose-проектов и dev-доменов `<project>.localhost` |
| `scenarios` | string[] | — | **обязательно**. Явный список всех сценариев проекта; каждая сценарная карта обязана содержать ровно эти ключи. Имена `^[a-z0-9-]+$`, без канонизации (`dev` ≠ `development`) |
| `gateway` | object | — | **обязательно**. Конфигурация общего шлюза по сценариям |
| `services` | object | — | **обязательно**. Сервисы проекта; ключ — имя сервиса `^[a-z0-9-]+$` |

Корневых `env`, `secrets`, `deploy`, `devGateway`, `runtime` в v3 **нет** — их заменили сценарные карты (Zero Scalars).

## Секция `gateway.<scenario>`

| Поле | Тип | Default | Описание |
|---|---|---|---|
| `httpPort` | number | — | HTTP-порт шлюза (обычно 80) |
| `httpsPort` | number | — | HTTPS-порт шлюза (обычно 443) |
| `admin` | boolean | false | Админ-эндпоинт Caddy |
| `acmeEmail` | string | — | Email для Let's Encrypt (prod/stage) |

## Поля сервиса (`services.<name>`)

Все поля, кроме `secrets`, — **карты сценариев**: значение для каждого ключа из корневого `scenarios`, пропуски запрещены.

| Поле | Тип | Описание |
|---|---|---|
| `runtime` | map | **обязательно**. Драйвер сценария: `{ "driver": "docker" \| "bun" }`. Host-сценарии (`bun`) пегас не поднимает — их запускает разработчик (`bun run dev`) |
| `image` | map | Docker-образ; обязателен для docker-сервисов без `build` (например `postgres:18-alpine`) |
| `build` | map | Сборка: `{ context, dockerfile, target, args }`; `null` в host-сценариях |
| `command` | map | Команда процесса в контейнере (переопределяет CMD образа) |
| `port` | map | Логический TCP-порт; обязателен при `domains`. Основа алиаса и `PEGAS_CONTEXT` |
| `ports` | map | Проброс на хост (compose-синтаксис); `[]` вне development — норма (закрытый сервис) |
| `publicHost` | map | **DNS-имя** (строка, не объект!) для публичного TCP-сервиса; Caddy его не маршрутизирует, TLS — ответственность сервиса |
| `domains` | map | HTTP-домены шлюза; строго для HTTP-сервисов. Не-HTTP наружу — `ports` + `publicHost` |
| `cors` | map | CORS-заголовки: `true` (все домены проекта) или объект `{ origins, methods, credentials }` |
| `env` | map | **Несекретные** значения конфигурации: на каждый ключ — карта сценариев. Значение `pegas://<имя-сервиса>` разворачивается во внутренний адрес при деплое |
| `secrets` | string[] | **не карта**. Имена секретных ключей (интерфейс зависимостей); значения — из `.env`/CI-хранилища, паритет 1:1 проверяет `pegas check` |
| `volumes` | map | Named-тома по сценариям (compose short syntax) |
| `dependsOn` | map | Зависимости: `{ "<имя>": { "condition": "service_healthy" \| "service_started" } }`; в host-сценариях — только пустой объект |
| `healthcheck` | map | Проба: `{ test, interval, timeout, retries }` (compose-формат) |

## Сценарные карты (Zero Scalars)

Значение каждого сценарно-зависимого поля — объект с ключами ровно из `scenarios`:

```jsonc
"port": { "development": 3000, "stage": 3000, "production": 3000 }
```

Скаляр на верхнем уровне поля — ошибка валидации. Это правило гарантирует,
что любое окружение описано явно, а не выводится из дефолтов.

## Service discovery: `pegas://`

Значение env-ключа вида `"pegas://<имя-сервиса>"` при генерации манифеста
разворачивается во внутренний адрес сети pegas-network:
`<scheme>://<projectId>-<scenario>-<service>:<port>`.
Схема определяется по образу целевого сервиса (redis, postgres, http).
Ссылка на host-сервис (`driver: "bun"`) — ошибка: внутренний адрес контейнерам недоступен.

## Доктрина env в коде

| Слой | Источник значения | Чтение в коде |
|---|---|---|
| Топология | `pegas.json` | SDK: `currentService()`, `services()` |
| Секреты | `.env` / CI | SDK: `secret()` |
| Несекретный app-конфиг | `services.*.env` | `process.env.MY_KEY` (ключ задекларирован) |

Подробнее и с примерами — [README](../../README.md#доктрина-доступа-к-конфигурации-в-коде).

## Эволюция контракта

Расширения схемы — не ломающие (SemVer minor). Ломающие изменения — только major
с явным планом миграции. Изменение топологии в репо всегда начинается с правки
`pegas.json`; `pegas check` обязан быть зелёным до коммита.
